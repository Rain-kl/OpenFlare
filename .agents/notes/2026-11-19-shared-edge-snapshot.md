# Edge 统一业务快照和配置应用

- OpenResty 和 Pingora 读取同一份业务快照。Pingora 发布记录引用 `source_version`。主控从发布时固化的快照和资源生成传输载荷。
- 两个引擎的发布指针使用同一个数据库事务更新。Pingora 回滚生成新序号，清理版本时保留仍被引用的快照。Edge 开发阶段的专用旧载荷已经移除。
- Rust 节点在单进程内运行控制面和数据面。候选配置与 Pages 包准备成功后保存到磁盘，再切换进程内快照。一次业务请求使用同一份快照。
- 请求入口与策略、回源、响应、资源和观测模块分离。发布检查涵盖本地模拟主控、源站和运行中的 Pingora。
- 生产迁移仍需对照 Linux 服务更新、完整的 OpenResty HTTP 行为以及缓存边界。HTTP/3 未接入。
