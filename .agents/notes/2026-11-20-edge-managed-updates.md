# Pingora 节点更新

控制台复用节点发布与更新接口。Pingora 发布按 `edge-v` 标签和 Linux 产物识别，手动请求固定到具体版本。节点通过协议能力声明是否支持托管更新。心跳从数据库读取管理设置，避免令牌认证缓存随心跳续期后继续提供旧设置。版本就绪确认按当前请求的 tag 条件更新，保留并发写入的新请求。

systemd 始终从管理员安装的二进制启动。非 root 服务进程在状态目录内暂存通过 SHA-256、版本和协议验证的文件。下一次启动只试运行一次，控制端心跳、监听和配置就绪后提交为活动版本，失败时回到先前的活动版本或最初安装的二进制。安装脚本手动替换入口时清理远程更新槽位，使手动指定版本生效。

更新检查独立于配置同步和心跳。变更目标时取消旧检查，手动请求优先于正式版定时检查。现有 Linux systemd 节点需先更新到声明此能力的版本。
