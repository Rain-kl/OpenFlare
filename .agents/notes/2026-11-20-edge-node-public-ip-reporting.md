# 边缘节点公网 IP 探测与主控 `/api/geoip` 兜底

- 原生 Pingora Edge 上报载荷未携带 `ip` 字段，控制端使用 `c.Request.RemoteAddr` 回退并直接落库，在反向代理或 Docker 网桥场景下统一记录为网关内网地址（如 `172.27.0.1`）。
- Edge 启动时优先扫描启用且非回环的本地网卡地址，通过统一 CIDR 规则排除全部内网及保留网段（`0.0.0.0/8`、`10.0.0.0/8`、`100.64.0.0/10`、`127.0.0.0/8`、`169.254.0.0/16`、`172.16.0.0/12`、`192.0.0.0/24`、`192.0.2.0/24`、`192.88.99.0/24`、`192.168.0.0/16`、`198.18.0.0/15`、`198.51.100.0/24`、`203.0.113.0/24`、`224.0.0.0/4`、`240.0.0.0/4` 及对应 IPv6 保留网段）；仅当节点不存在非回环 IPv4 地址时才直接采纳网卡公网 IPv6，避免双栈 NAT 节点绕过 IPv4 出口探测。
- 若网卡未获取到可用公网地址，Edge 在启动及每分钟依次探测 `https://api.ip.sb/ip`、`https://ip.me`（使用 `curl/8.5.0` User-Agent 以获取纯文本 IP）和 `https://api.ip2location.io/`，全部失败后再请求控制端新增的 `GET /api/geoip`；所有来源均无法取得非保留公网地址时返回 `0.0.0.0`。
- 控制端新增 `GET /api/geoip` 返回主控观察到的请求方 IP，并在节点注册、心跳、GeoIP 填充与 Cloudflare DNS 指向校验中统一拒绝将内网或 `0.0.0.0` 视为有效公网 IP。
