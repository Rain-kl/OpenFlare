# 站点快照自动同步与失败恢复

控制端从业务表编译 Pingora 快照。Goose 触发器在源数据事务中递增单行修订号，API 写请求完成后唤醒编译循环，后台写入及丢失唤醒由定期检查处理。编译使用主库读取，提交时比较源修订号，避免使用过时的配置覆盖新写入。摘要未变化时仅推进编译游标。最后一条路由关闭后生成空快照。配置版本管理路由和界面已移除，数据库继续保存内部修订，节点可自主恢复。

节点持久化最新观测到的修订元数据，心跳同时提交最新修订和当前服务修订。控制端对节点已知的修订仅发送标识和摘要。新配置通过校验和持久化后替换当前健康快照。校验或应用失败时记录失败修订，保持健康快照并报告失败。同一失败修订在本次进程中跳过后续拉取。强制同步、进程重启和更高的修订可触发下一次尝试。拉取接口的传输或并发更新错误继续按心跳重试。

集成测试通过真实 SQLite 迁移验证保存后自动编译、编译失败保留上一份快照、陈旧编译提交被拒绝、按摘要拉取和空快照。边缘冒烟测试覆盖重复拉取抑制、强制同步、重启重试以及新修订后的流量恢复。
