# Pingora 性能策略

在控制台打开「性能策略」，为不同规格或用途的边缘节点创建策略。新策略预填参数，表单提供用途、单位和允许的取值范围。

1. 选择「新建策略」，输入名称并调整运行时、回源连接、HTTP/2、TLS 线程池、监听器和缓存参数。
2. 保存后选择「分配节点」，按名称或节点 ID 查找，可以批量选择。
3. 保存分配。一个节点使用一条策略，重新分配后改用新策略。取消分配或删除策略后，节点改用默认策略。

未分配其他策略的节点自动使用列表顶部的「默认策略」，包括新加入的节点。默认策略可以编辑，初始开启「自动配置」。

三个规格预置策略适合用作常见服务器规格的起点，可直接分配或编辑。

| 规格 | 工作线程 | 空闲回源连接池 | 下游 HTTP/2 并发流 | 内存缓存容量 |
| --- | ---: | ---: | ---: | ---: |
| 1C1G | 1 | 64 | 64 | 32 MiB |
| 2C2G | 2 | 128 | 128 | 64 MiB |
| 4C8G | 4 | 256 | 256 | 256 MiB |

开启「自动配置」后，节点启动时按进程可用的 CPU 核心数和内存上限计算工作线程数与空闲回源连接池容量。Linux 节点会读取常见 cgroup 挂载下的内存上限。关闭后可手动设置两项参数。

自动模式为每个工作线程预留 768 MiB 的估算预算，至少保留一个线程。回源连接池同时受线程数和内存限制，容量按工作线程配置。例如，检测到 1 核和 1 GiB、2 核和 2 GiB、4 核和 8 GiB 时，分别配置 1、2、4 个工作线程，每个线程对应的空闲回源连接池容量为 64、128、256。节点启动日志会记录实际应用的两个参数。

策略保存后，控制端立即通知已连接的节点。回源超时、TLS 校验、上游 HTTP/2 和部分缓存参数对新请求热生效。线程数、连接池容量、下游 HTTP/2、监听器或缓存总容量等启动参数变化时，节点自动排空连接并重新启动工作线程，期间可能短暂影响新连接。离线节点重新连接后会获取当前分配。

新策略默认验证 HTTPS 源站的证书和主机名。配置缓存时，需在站点详情的「缓存」页启用对应规则，策略中的节点缓存开关控制这些规则能否在该节点生效。预置参数应结合实际吞吐、并发、内存和源站延迟调整。


## 缓存存储

在性能策略的「缓存」页设置节点的存储容量和磁盘并发。启用「节点缓存」后，还需在站点详情启用相应的缓存规则。

| 参数 | 默认值 | 作用 |
| --- | ---: | --- |
| 内存缓存容量 | 128 MiB | TinyUFO 内存缓存容量。启用磁盘缓存后用于存放高频访问的小对象 |
| 磁盘缓存容量 | 0 MiB | 填正数启用磁盘存储，并在写入时按最近访问时间淘汰对象 |
| 磁盘缓存清理时间 | 172800 秒 | 定期清理超过此时间未访问的文件 |
| 磁盘并发读取上限 | 32 | 达到上限时，缓存未命中的请求从源站获取 |
| 磁盘并发写入上限 | 16 | 达到上限时，本次响应跳过落盘 |

磁盘缓存保存在节点状态目录下的 `http-cache`，常见路径为 `/var/lib/openflare-edge/http-cache`。节点重启后可以继续使用有效的磁盘缓存。节点状态目录中的站点快照更新后，新请求使用新的缓存键。修改存储参数会触发节点自动重载。磁盘缓存初始化失败时，节点记录日志并切换到内存缓存。

磁盘缓存和内存热层由 [pingap-cache](https://github.com/vicanso/pingap/tree/a2c7975b1573afc8480efae58167bd0a362ed53c/pingap-cache) 提供。磁盘模式允许单个对象大于内存热层容量。节点仍以可用内存限制单个对象的有效缓存上限，因为读取和写入磁盘对象时需要在内存中暂存对象。
