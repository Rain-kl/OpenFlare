# 内网穿透与隧道使用

本文档介绍 OpenFlare 内网穿透子系统的核心概念、控制域界面操作流程，以及 L7 Web 站点与 L4 TCP/UDP 服务的发布与故障排查方法。

---

## 核心概念

在 **「内网穿透」** 控制台（`/tunnels`）中，资源体系由以下五个核心对象组成：

| 对象 | 说明 | 对应实体与行为 |
| :--- | :--- | :--- |
| **中继池（Relay Pool）** | 中继节点与隧道的高可用调度分组，控制传输协议策略、跨区高可用中继数量及默认 CIDR 安全边界 | `w_tunnel_relay_pools`；支持设置 `preferred_transport`（`auto` / `noise` / `websocket` / `tcp`）、`fallback_transports` 与默认 `ha_relays` |
| **中继节点（Relay）** | 运行 `openflare-relay` 的公网服务器，负责终结加密隧道并提供 Relay Gateway 与 L4 端口监听 | `w_tunnel_relays`；支持 `zone_tag` 故障域标记、排水（`draining`）、同机 Edge 共置绑定与一键紧急隔离 |
| **穿透隧道（Tunnel）** | 逻辑穿透实例，归属于指定中继池，可由多个 `openflared` 连接器副本联合承载 | `w_tunnels`；配置独享允许/禁止目标 CIDR、支持令牌轮换与紧急隔离 |
| **连接器（Connector）** | 内网部署的 `openflared` 运行副本，多副本可同时在线构成双活冗余，并通过 Make-Before-Break 自动挑选池内最优中继 | `w_tunnel_connectors` 与 `w_tunnel_attachments`；自动持久化 `connector_id` 并上报版本、出口 IP 与每条附着链路 RTT |
| **转发服务与 L7 上游** | 分为在隧道详情页配置的 **L4 服务（TCP/UDP）**，以及在 **「反向代理」** 绑定 `tunnel_id` 的 **L7 网站上游** | L4 写入 `w_tunnel_services`；L7 由 Pingora Edge 读取 `tunnel-routing.v1` 经 Relay Gateway 调度入隧道 |

---

## 标准配置流程

### 第一步：准备中继池（Relay Pool）

系统迁移初始化后会创建一个默认中继池。进入 **「内网穿透 → 中继池」** 页签：
1. 根据网络环境确认默认传输偏好（通常保持 `auto`，按 `noise → websocket → tcp` 顺序回退）。
2. 设置 **高可用中继数（HA Relays）**（默认为 `2`，建议生产环境在同一中继池内跨不同可用区部署至少 2 台 Relay）。
3. 核对默认 **禁止目标 CIDR**（默认包含云主机元数据地址 `169.254.169.254/32`）与 **允许目标 CIDR**（留空表示不限制允许范围，仅受禁止清单约束）。

### 第二步：部署公网中继节点（Relay）

1. 在 **「内网穿透 → 中继节点」** 页签，点击 **「新增中继」**（或直接复制页面上方的全局 **自动发现部署命令**）。
2. 如需精准规划跨可用区容灾，可在创建中继时填写 **可用区标签（`zone_tag`）**，并在该 Relay 与某台 Edge 同机部署时选择对应的 **共置 Edge 节点**。
3. 在公网服务器上按生成的 `oftok1_` 命令运行 `openflare-relay`（脚本与 Docker 用法见 [部署 Relay](../deployment/relay.md)）。
4. 确认该 Relay 状态变为 **在线（Online）** 且 WebSocket 状态为已连接。

### 第三步：创建穿透隧道并启动连接器（OpenFlared）

1. 切换至 **「内网穿透 → 隧道列表」** 页签，点击 **「新建隧道」**。
2. 选择所属 **中继池**、传输偏好及回源安全 CIDR 规则（如仅允许 `127.0.0.1/32` 与 `192.168.10.0/24`）。
3. 保存后系统弹窗展示专属 `oftok1_` 引导令牌与安装命令。在内网主机上执行部署命令（参考 [部署 OpenFlared](../deployment/openflared.md)）。
4. 打开隧道详情页，确认 **连接器列表** 显示在线实例，且 **附着链路** 已按预期连接至池内在线的 Relay 节点。

### 第四步 A：暴露 L7 Web / WebSocket 服务（推荐）

L7 服务直接享受 Pingora Edge 的公网 TLS 自动证书、WAF 安全规则与 PoW 防护：
1. 进入 **「反向代理 → 新建规则」**（或编辑现有站点规则）。
2. 在反向代理设置中，将 **上游类型** 选择为 **「内网穿透（Tunnel）」**。
3. 选择上述在线的 **隧道**，填写内网可访问的 **目标源站地址**（例如 `http://127.0.0.1:8080` 或 `https://192.168.1.20:8443`）。
4. 若内网源站使用自签名 HTTPS 证书，可开启 **跳过内网 HTTPS 证书校验（`insecure_skip_verify`）**。
5. 保存路由后，Pingora Edge 通过 `tunnel-routing.v1` 自动更新网关路由，即可通过公网域名访问内网站点。

### 第四步 B：暴露 L4 TCP / UDP 服务

如需对外提供 SSH、数据库或游戏联机等非 HTTP 服务：
1. 进入目标隧道的 **「隧道详情」** 页面，在「服务列表」点击 **「新增服务」**。
2. 选择协议类型（`tcp` 或 `udp`），选定承接流量的在线 **中继节点** 与公网 **监听端口**（不得与中继控制端口 `7443`/`7444`/`8443` 或其他服务端口冲突），并填入内网 **目标地址**（如 `127.0.0.1:22`）。
3. 启用并保存后，Relay 与 OpenFlared 通过控制流同步并在进程内热加载对应的 rathole 服务实例，随即可以通过 `<Relay公网IP>:<监听端口>` 访问内网服务。

## 高可用切换与运维管控

* **中继平滑排水维护**：在中继详情页开启 **排水模式（Draining）** 后，控制面将停止向连接器下发该中继；各 `openflared` 实例会在后续探测周期中建立至其他健康中继的替代隧道并平滑迁移活跃会话，完成后即可安全重启或下线该中继节点。
* **多连接器双活冗余**：为同一条隧道部署多个 `openflared` 进程时，Relay Gateway 与内嵌 `rathole` 会自动感知全部在线连接器并在单副本断线时无缝切换。
* **紧急隔离（Quarantine）与密钥轮换**：若怀疑中继或内网连接器凭证泄露，可在对应详情页执行 **「紧急隔离」** 立即切断隧道接入并吊销令牌；确认环境安全后点击 **「解除隔离」** 即可签发全新凭证重新上线。

## 常见故障排查

### 1. 连接器无法上线或状态长期处于「离线」
* 检查内网机器能否出网访问引导令牌内的 Server 控制端地址以及 Relay 的 `7443`/`7444` 端口（及探活端口 `8443`）。
* 确认目标中继池内至少存在 1 台处于在线且未启用 **排水** 或 **隔离** 状态的中继节点。
* 若控制台曾执行令牌轮换或解除隔离，需使用新生成的 `oftok1_` 令牌重新启动或更新宿主机上的令牌文件（systemd 服务默认存放在 `/var/lib/openflared/bootstrap-token`）。

### 2. 公网访问域名返回 HTTP 403 Forbidden 或 502 Bad Gateway
* **403 Forbidden（来自连接器 Ingress）**：检查隧道或中继池配置的 **允许/禁止目标 CIDR** 是否封锁了目标内网地址（例如回源目标解析到 `169.254.169.254` 或未包含在非空的 `allowed_cidrs` 列表中）。
* **502 Bad Gateway**：确认内网服务正在运行且可从 `openflared` 所在网络命名空间连通；若使用了 HTTPS 内网源站但采用自签名证书，请在反向代理配置中开启 `insecure_skip_verify`。

### 3. L4 服务保存失败或无法监听
* 核对所选 **监听端口** 是否与该中继的传输端口（`7443`）、WebSocket 端口（`7444`）、网关端口（`8443`）或其他已启用的 L4 服务端口重叠，以及云服务器安全组和系统防火墙是否已放行对应端口。
