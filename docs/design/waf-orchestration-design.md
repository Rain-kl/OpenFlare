# WAF 可编排规则设计

OpenFlare WAF 基于可视化有向无环图（DAG）编排规则，控制面校验并编译规则拓扑，由 `openflare-edge` 在请求阶段执行流程匹配、`zentinel-modsec` OWASP CRS 攻击检测及边缘 PoW 挑战，同时通过独立的清单通道同步 IP 组与全局请求白名单。

---

## 1. 安全判定边界与求值顺序

`openflare-edge` 在每次路由请求进入回源或 Pages 静态服务前按固定顺序执行防护检查：

1. **全局请求白名单（`waf-request-whitelist-v1`）**：控制面将全局白名单随快照下发，边缘预编译精确、前缀、后缀与正则路径规则（按精确域名与单层 `*.suffix` 匹配 Host）。命中请求白名单时，直接跳过全部 WAF 规则流及请求体检测。
2. **全局 WAF 规则组**：所有启用中的全局规则固定最先执行，不参与路由级排序。
3. **路由绑定 WAF 规则组**：按站点的绑定顺序依次执行。
   * 单条规则抵达「阻止」节点时立即输出配置的 HTTP 状态码与响应体并终止请求，同时记录 `WafAudit`；
   * 抵达「通过」节点表示当前规则完成，继续执行后续规则；全部启用规则均通过后才进入后续限流/缓存/回源阶段；
   * 执行器遇到未知节点、悬空出口或超出步数上限时默认拒绝放行并记错误日志，防止损坏策略导致意外放行。
4. **独立 PoW 策略**：由 [PoW 防护设计](./pow-design.md) 执行。若站点已启用独立 PoW 策略，旧版 WAF 图内兼容保留的 PoW 节点会自动跳过，避免重复挑战。

### 地域解析与共享 IP 匹配

* **GeoIP 弱依赖原则**：`openflare-edge` 在 `$STATE_DIR` 加载并按 24 小时周期（失败 15 分钟重试、单文件上限 `128 MiB`）更新 `GeoLite2-City.mmdb` 与 `GeoLite2-Country.mmdb`（优先 City 库解析国家与 ISO-3166-2 行政区，缺失时回落 Country 库）。当本地 MMDB 不可用或客户端 IP 无匹配记录时，地域匹配节点按未命中处理，不中断 IP 匹配与反向代理主链路。
* **共享 IP / CIDR 匹配器**：WAF 与 PoW 共享 `edge/src/policy/mod.rs::ip_in_cidr`，统一支持 IPv4、IPv6 及多种文本表达形式的掩码比对。

## 2. DAG 节点与运行语义

新增 WAF 规则时仅需填写名称，系统自动生成初始合法图 `开始 → 通过`，随后在 React Flow 画布上编排处理单元。系统不支持循环、任意脚本节点、子图调用或跨规则跳转。

| 节点类型 | 数量约束 | 输入 | 输出 | 配置与运行时语义 |
| :--- | :--- | :--- | :--- | :--- |
| **开始 (`start`)** | 每图恰好 1 个 | 无 | `next` | 图入口 |
| **通过 (`allow`)** | 每图恰好 1 个 | `>= 1` | 无 | 当前规则放行出口 |
| **阻止 (`block`)** | 可多个 | `>= 1` | 无 | HTTP 状态码（默认 `403`）与可选 HTML 响应体 |
| **IP 匹配 (`ip_match`)** | 可多个 | `>= 1` | `true`、`false` | 配置直填 IP、CIDR 与引用 IP 组 ID（匹配为 `true` 或按连线决定拦截/放行） |
| **地域匹配 (`geo_match`)** | 可多个 | `>= 1` | `true`、`false` | 国家代码与 ISO 3166-2 一级行政区代码 |
| **UA 检查 (`ua_check`)** | 可多个 | `>= 1` | `true`、`false` | 求值顺序：要求携带 UA → 屏蔽爬虫/非正常 UA/自定义子串 → 浏览器/OS 白名单（`and`/`or`） |
| **攻击防护 (`attack_protection`)** | 可多个 | `>= 1` | `true`、`false` | 选择攻击防护规则组（支持 17 类 OWASP CRS 请求规则分类、`off`/`observe`/`essential`/`balanced`/`strict` 档位及单规则覆盖），`zentinel-modsec` 检测 URI、请求头及上限 `64 KiB` 的请求体；仅观察模式走 `true` 并记审计日志，命中拦截条件走 `false` |
| **旧 PoW（兼容）** | 保留已有节点 | `>= 1` | `next` | 算法、难度、会话 TTL、挑战 TTL；已配置独立站点 PoW 时自动跳过 |

> [!NOTE]
> `attack_protection` 加载请求阶段规则（映射至 OpenFlare 17 个类别），不启用响应体检测或 CRS 异常评分累计模式，并补充 XXE 与 ASP 代码注入检测规则。同一快照内相同级别组合的检测节点共享编译结果以控制内存开销。

## 3. 控制面校验、编译与 IP 组同步

### 3.1 双模型与图结构约束

* **编辑态 vs 运行态**：前端提交带节点位置与 `revision` 的版本化图 JSON（保存时校验乐观锁 `revision`，冲突返回 HTTP 409）；控制面 `CompileRuleGraph` 剥离坐标与标签，将出边编译为节点 ID 查找表并校验以下约束（单条规则上限 `128` 节点、`256` 边、`256 KiB` 编辑态 JSON）：
  * 有向无环（DAG），禁止自环；
  * 恰好 1 个 `start`、1 个 `allow`，至少 1 个可达终态；
  * 除终态外不得悬空，所有非 `start` 节点均从 `start` 可达；
  * 条件节点必须同时连接 `true` 与 `false` 出口，且同一端口不可多连。

### 3.2 IP 组独立刷新 (`waf.ip-group.v1/<id>`)

* 控制面支持 `manual`（手动列表）、`automatic`（按访问特征表达式 `expr-lang` 定期自动拉黑）与 `subscription`（外部文本或 JSON 订阅）三类 IP 组。
* 规则拓扑随 `sites.v1` 下发，IP 组成员则通过 `config_sync v1` 的独立资源键 `waf.ip-group.v1/<id>` 同步，单次完整运行时 IP 组快照上限 **`20 MiB`**（`protocol.MaxWAFIPGroupSnapshotBytes`）。
* 节点通过 SHA-256 摘要增量拉取并在内存中原子替换对应 IP 组；若拉取、校验或 CRS 规则编译失败，节点维持上一健康快照继续防护，不因配置损坏放行流量。

---

## 4. API 与编辑器要点

* 管理端入口与接口位于 `internal/apps/openflare/waf/`：规则元数据、图保存（`revision` 防覆盖）、路由绑定（有序规则 ID 数组）、全局白名单、攻击防护规则组与 IP 组 CRUD/手动同步各自独立操作。
* 编辑器画布基于 React Flow 提供缩放、平移、框选、自动布局、节点删除级联清理关联边与未保存离开提醒；地域匹配属性使用可搜索的国家与 ISO 3166-2 行政区选择器；审计明细随访问日志写入 `of_node_access_logs`（`waf_action` 与 `waf_audit` 列）。
