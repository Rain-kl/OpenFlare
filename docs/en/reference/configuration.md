# Configuration

You will learn: which config sources OpenFlare Server, frontend build, Agent, Relay, and OpenFlared support, what config fields and env vars exist, and their defaults and behavior.

This document summarizes all configuration items supported by the current OpenFlare version.

---

## Config Sources

### 1. Server Config Sources
- **Config file**: reads `config.yaml` in the same directory at startup by default (overridable via the `CONFIG_PATH` env var).
- **Env vars**: every field in the config file can be overridden by an `UPPER_SNAKE_CASE` env var (env vars take precedence over `config.yaml`).
- **System runtime config**: stored in the `w_system_configs` table in the relational DB. These can be hot-updated and take effect dynamically via the admin UI or system API.

### 2. Agent / Relay / OpenFlared Config Sources
- **CLI args**: `-config` specifies the config file (JSON format).
- **Config file**: e.g. `relay.json`, `flared.json`.
- **Override env vars**: specific env vars can override connection addresses and Token credentials in the config file.

## Server CLI Args

```bash
# specify a config file when starting the Server
CONFIG_PATH=/path/to/custom-config.yaml ./bin/openflare-server all
```

Supported sub-service commands (fused/single-process mode):
- `all`: starts all services in one process (API + Worker + Scheduler, default).
- `api`: starts only the API service for the admin panel and node communication.
- `worker`: starts only the background-task Asynq Worker service.
- `scheduler`: starts only the scheduled-task Scheduler service.
- `reset-passwd`: resets the password of a specified account (supports `--user` and `--password` flags).

### 6. Edge Security and Rate Limiting Options

OpenFlare edge proxies operate exclusively on the Pingora architecture. Obsolete OpenResty / Nginx configuration directives (such as `worker_processes`, `worker_connections`, `worker_rlimit_nofile`, and `keepalive_timeout`) have been removed. Edge runtime parameters, upstream connection pools, HTTP/2, TLS listeners, and proxy caching policies are managed via the console under "Performance Policies" and distributed to edge nodes (see [Pingora Performance Policies](../guide/performance-policies.md)).

The system retains generalized edge security and traffic limit settings (`edge_*`), configurable under "System Management → System Configuration → Business Configuration":

| Key | Type | Description | Default |
| --- | --- | --- | --- |
| `edge_trusted_proxy_cidrs` | `string` (JSON array) | IPv4/IPv6 CIDR list authorized to pass `CF-Connecting-IP`; defaults to Cloudflare's 22 official IPv4/IPv6 ranges; setting explicitly to `[]` disables trust | Cloudflare official ranges |
| `edge_default_limit_conn_per_server` | `int` | default per-server concurrent connection limit when unconfigured; `0` disables | `0` |
| `edge_default_limit_conn_per_ip` | `int` | default per-IP concurrent connection limit when unconfigured; `0` disables | `0` |
| `edge_default_limit_rate` | `string` | default bandwidth limit per request when unconfigured (e.g. `512k`); empty disables | empty |
| `edge_default_limit_req_per_ip` | `string` | default per-IP request frequency limit when unconfigured (e.g. `10r/s`, `100r/m`); empty disables | empty |

In the admin panel, edit `edge_trusted_proxy_cidrs` under "System Management → System Configuration → Business Configuration". The default value contains Cloudflare's official 22 IPv4 and IPv6 CIDRs. To trust additional reverse proxy hops, append their CIDRs to the array (e.g. `10.2.0.227/32`). Explicit `[]` disables trusted proxy header handling. Pingora extracts `CF-Connecting-IP` only from trusted origins, applying the recovered client address to access logs, WAF rules, and upstream `X-Real-IP`.

### 7. Origin Error Page

Global origin error page configuration. Automatically synced to edge nodes via site snapshots. Affects only **reverse proxy** routes; Pages static site routes remain unaffected. Admin entry: "Website Management → Error Pages". See [Origin Error Page Design](../design/origin-error-page.md).

| Key | Type | Description | Default |
| --- | --- | --- | --- |
| `origin_error_page_enabled` | `bool` | enable the global origin error page. When enabled, matching status codes from the origin or gateway are replaced with custom/default HTML while the **HTTP status code is preserved**; when disabled, origin responses pass through untouched | `true` |
| `origin_error_page_get_only` | `bool` | apply exclusively to **GET** requests. When enabled, only GET requests receive the custom error page; POST/PUT and other methods pass through raw origin responses | `false` |
| `origin_error_page_status_codes` | `json` | status code selector JSON array. Supports individual codes (e.g. `522`) and closed ranges (e.g. `500-599`); range limits must be in **400–599** with `lo ≤ hi` | `["500-599"]` |
| `origin_error_page_html` | `string` | custom HTML template. An empty string uses the built-in minimal white OpenFlare template; supports placeholders `{{status}}` and `{{host}}`. Max **256 KiB** | empty |

## Pingora Edge Startup Arguments

`openflare-edge run` connects to the control plane using `--server-url`, `--token-type discovery|node`, `--token-file`, and `--state-dir`. Listening sockets are specified via `--http-listen` and optionally `--tls-listen`. Installer-managed services default to ports 80 and 443 with state stored in `/var/lib/openflare-edge`. Pass `--upgrade` when upgrading active configurations.
